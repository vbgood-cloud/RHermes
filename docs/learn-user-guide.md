## 第 1 章 快速开始（含初始配置引导）

### 1.1 一句话认识 `/learn`

`/learn` 是 RHermes 内置的**知识库学习模式**。它把"一份资料"变成"一个可复习的知识图谱"，再用**引导式教学 + 间隔复习**带你一个知识点一个知识点地学下去，最后给你一份可视化战绩。

一句话链路：

```
文档 / 目录 / 主题
      ↓  抽取知识点
   知识图谱（SVG，节点随遗忘自动变浅）
      ↓  引导教学
  讲解 → 提问 → 判分 → 下一个
      ↓  间隔复习（艾宾浩斯 + SM-2 难度系数）
   复习面板 / Bento 战绩 / 导出迁移
```

**能力矩阵**（7 个内部工具 + 复位）：

| 工具 | 作用 | 你什么时候会用到 |
|------|------|------------------|
| `kb_create` | 建库（节点 + 关系） | `/learn <文件>`、`/learn <目录>`、`/learn <名称> <主题>` |
| `kb_append` | 向已有库追加节点 | 大文件/多文件分段建库时自动使用 |
| `kb_graph` | 生成图谱 HTML | 建库后、每学 3–5 个节点自动刷新 |
| `kb_learn` | 取"下一个该学的点" | 每讲一个知识点前 |
| `kb_quiz` | 判分并回填掌握度 | 每次提问后（含掌握度更新） |
| `kb_stats` | 学习统计 / Bento | `/summary`、`/stop` 收官 |
| `kb_list` | 列出所有知识库 | `/learn list` |
| `kb_reset` | 复位学习进度 | `/learn reset <名称>` |

**三类典型场景**：

- **自学新领域**：`/learn 数据结构 我零基础` → 让模型先建库，再逐点教你。
- **把资料变成可复习图谱**：`/learn D:\课件\计算机网络.pdf` → 从课件建库并开始教学。
- **教师建库分发给学生**：教师建好库后 `/learn export 计算机网络 --kb` → 学生 `/learn import` 后从零学，进度互不干扰。

### 1.2 首次启动与配置（约 3 分钟）

RHermes 采用**可移动模式（Portable Mode）**：所有配置与数据都放在**可执行文件同目录**下，不写注册表、不写系统盘用户目录。这意味着：

- `config.toml`（非敏感配置）与 `.env`（API Key）放在 **`rhermes.exe` 所在目录**；
- 所有运行时数据（含知识库）放在 **`<exe_dir>/home/`** 下。

> ⚠️ **它没有 `--config` 参数**。程序以"可执行文件所在目录"为锚点自动定位配置。所以**换目录就等于换了一套配置和数据**——这也是它 USB 可运行的原因。

#### 步骤 1：运行初始化向导 `setup`

```bash
rhermes setup
```

向导会依次引导你完成首次配置：

1. 创建数据目录（`home/`）
2. 选择 AI 提供商
3. 确认 API 地址
4. 配置 API Key
5. 查询并选择模型

一路确认即可，向导会自动在 exe 同目录生成 `config.toml` 并写入配置。

> 💡 若你的版本提示没有 `setup` 子命令，改用 `rhermes init`——它是同一套初始化向导。

#### 步骤 2（可选）：手工核对配置与 API Key

- **非敏感配置**在 `config.toml`（exe 同目录）；
- **API Key** 推荐放在 **`.env`**（同目录，不进版本库）：

```dotenv
DEEPSEEK_API_KEY=sk-********************************
```

学习模式的讲解与出题都依赖主模型，因此**必须先有一个可用的模型与 Key**；否则 `/learn` 只能做本地操作（list/export/import/reset），无法建库与教学。

> 📌 其他与命令的关系：`config init` 只生成带注释的配置模板；`gateway setup` 配通道；`mcp setup` 配 MCP。**首次初始化用 `setup` 即可。**

#### 步骤 3：确认 `[knowledge]` 段（可省略）

`/learn` 只有一个配置项，写在 `config.toml`：

```toml
[knowledge]
# 有效掌握度低于此值即触发复习（0-100，默认 60）
# effective = mastery × 2^(-Δt/稳定性)，effective < review_floor → 到期复习
review_floor = 60
```

**不写也能用**——默认就是 60。想调整复习强度，见 §2.2。

#### 步骤 4：自检

```bash
rhermes config check
```

#### 步骤 5（可选）：配置微信通道

想让 `/learn` 也能在微信上使用，见下一节 **§1.3 快速配置微信通道**——扫码登录即可，无需注册应用。

### 1.3 快速配置微信通道（可选，约 2 分钟）

RHermes 支持两种微信接入方式：

| 方式 | 适用场景 | 特点 |
|------|----------|------|
| **微信个号（iLink Bot）** ⭐ 推荐 | 个人自学 | 扫码登录你自己的微信，**无需注册应用** |
| 企业微信 Bot（WeCom） | 团队 / 教学班 | 需在企业微信管理后台建自建应用 + 群机器人 |

下面以**推荐的"微信个号"**为例。

#### 方式 A：交互向导（最省事）

```bash
rhermes gateway setup
```

向导分三步：① 勾选要启用的通道（选 **wechat**）→ ② 填微信参数（token 保存路径默认 `home/wechat_token.txt`、轮询间隔默认 2 秒、可选代理）→ ③ 确认运行参数。

之后可随时用 `rhermes gateway channel list` / `enable wechat` / `disable wechat` 调整通道启停。

#### 方式 B：手工编辑 `config.toml`

```toml
[channels.wechat]
enabled = true
# 扫码成功后 token 自动写入此文件，下次启动免扫码
token_path = "home/wechat_token.txt"
# 消息轮询间隔（秒，默认 2）
poll_interval_secs = 2
# 网络需要代理时取消注释
# proxy = "http://127.0.0.1:7890"
```

#### 启动并扫码

任选其一：

```bash
rhermes                 # TUI 模式：一边用终端、一边把微信挂上（推荐）
# 或
rhermes gateway start   # 守护模式：无界面后台常驻（适合服务器/长期在线）
rhermes gateway status  # 查看运行状态
```

启动后会依次出现：

1. ✅ 终端里的 **ASCII 二维码**（██ 空格矩阵）
2. ✅ **自动弹出一张清晰的二维码图片** `wechat_qrcode.png`（调用系统默认看图程序打开）——**手机扫这张更清楚**
3. ✅ 提示 `📱 请用微信扫描上方二维码登录`

用手机微信扫描**自动弹出的那张清晰图片**即可。**登录成功后 token 存入 `token_path`，下次启动免扫码。**

> 🔎 **如果二维码图片没有自动弹出，去哪里找？**
>
> 自动弹出依赖系统看图程序，以下情况可能不弹窗：无桌面的服务器、图片默认打开方式未关联、被杀毒软件拦截。按下面顺序即可拿到二维码：
>
> 1. **去「启动目录」找文件**——二维码图片保存在**你启动 `rhermes` 时所在的当前目录**（既不是 exe 所在目录，也不是 `home/`）：
>    - `rhermes`（TUI）或单通道守护模式 → 文件名 **`wechat_qrcode.png`**
>    - `rhermes gateway start`（多通道守护）→ 文件名 **`wechat_qrcode.<通道名>.png`**，微信通道即 **`wechat_qrcode.wechat.png`**
>    - 例：在 `e:\ai\new` 目录下启动，文件就是 `e:\ai\new\wechat_qrcode.png`
> 2. **手动打开**：到该目录双击这张 PNG，用任意看图软件打开后手机扫描；
> 3. **扫终端里的 ASCII 二维码**：文字版同样可扫，只是像素较大、小屏不易对准；
> 4. **复制扫码链接**：控制台会打印 `🔗 扫码链接: https://...`，可复制到手机浏览器打开。
>
> 💡 若希望图片固定落在某个目录，**先 `cd` 到该目录再启动 `rhermes`**，二维码就会存到那里。

#### 验证与使用

- 扫码后，用微信给自己（或"文件传输助手"）发一条消息，RHermes 会自动接收处理；
- 直接在微信里发 `/learn <路径或名称>`，即可在微信上建库、学习、`/summary`、`/stop`，行为与 TUI 完全一致；
- 微信通道下 `/learn` 建库期间会收到**每分钟心跳**（TUI 因有实时进度条而跳过）。

> ⚠️ **注意事项**
> - **同一个微信登录态不要在多个程序里同时启用**（会互相抢占消息轮询）——一个部署挂一个即可。
> - 二维码约 2 分钟过期，程序会自动重新获取，无需手动刷新；扫码无反应时先看 `rhermes.log`，多为代理问题。
> - 网络受限时在 `[channels.wechat]` 配 `proxy`；`[proxy]` 段已默认把 `*.weixin.qq.com` 放进 `no_proxy`。
> - 企业微信（WeCom）需先在管理后台建自建应用，拿到 `corp_id` / `agent_id` / `secret`（`secret` 写 `.env` 的 `WECOM_SECRET`），详见 `docs/wechat-setup.md`。

### 1.4 跑通你的第一个知识库（三步）

> 📁 **强烈建议：把学习资料先放进 `home/` 下的子目录**（如 `<exe_dir>/home/materials/`）。
> 原因：Agent 读取文件时只放行**工作目录**与 **`home/`（data_root）** 两类路径，资料放在 home 下可确保"目录建库/分段读取"在任何启动目录下都能读通，且随程序一起便携迁移。详见 §5.1。

```bash
rhermes                   # 进入 TUI 交互模式
```

把资料放到 `home/materials/` 后，在输入框里：

```
/learn home/materials/线性代数.pdf
```

然后你只需要**跟着它走**：它讲解 → 你回答 → 它出题 → 你作答 → 它判分 → 进入下一个点。

想停下来时：

```
/stop                     # 退出学习模式，并生成 Bento 战绩
```

## 第 2 章 配置详解

### 2.1 配置体系与文件定位

| 文件 | 位置 | 内容 | 是否进版本库 |
|------|------|------|--------------|
| `config.toml` | `<exe_dir>/` | 非敏感配置（模型、通道、`[knowledge]` 等） | 视仓库而定 |
| `.env` | `<exe_dir>/` | API Key 等敏感项 | ❌ 已忽略 |
| `home/` | `<exe_dir>/home/` | 全部运行时数据（含知识库） | ❌ 已忽略 |

**定位口诀**：程序在哪，配置和数据就在哪。把整个目录拷到 U 盘，插到另一台机器上，知识库与学习进度原样带走。

### 2.2 `[knowledge].review_floor` 详解（唯一的学习相关配置）

`review_floor` 是**复习红线**：当某知识点的**当前有效掌握度**低于它，就判定为"该复习了"。

```toml
[knowledge]
review_floor = 60    # 0-100，默认 60
```

它的数学含义：

```
effective_mastery = mastery × 2^(-Δt/S)
effective_mastery < review_floor  →  到期复习
```

- `mastery`：历史掌握度（永不衰减的基线）
- `Δt`：距上次复习的天数
- `S`：记忆半衰期（天），随每次测验分数伸缩

**调参建议**：

| 场景 | 建议值 | 效果 |
|------|--------|------|
| 应试冲刺 / 要求长期牢固 | **75–85** | 更早触发复习，要求更高的保持率 |
| 常规学习（默认） | **60** | 平衡：明显遗忘才复习 |
| 泛读 / 只求认识 | **40–50** | 容忍更多衰减，复习频率低 |

> 记忆锚：`review_floor = 60` 意味着"当今天真实还记得的部分不足 60% 时，就重新安排复习"。

### 2.3 数据目录全图

所有路径都相对 **`<exe_dir>/home/`**（即 `data_root`）：

| 路径 | 内容 | 命名规则 |
|------|------|----------|
| `home/knowledge/kb.db` | **知识库主数据库**（SQLite，独立于长期记忆库） | 固定名 |
| `home/knowledge/graphs/<库名>.html` | 知识图谱（SVG，浏览器打开） | 库名清洗后（非字母数字转 `_`） |
| `home/knowledge/bento/<库名>.html` | 战绩 Bento 面板 | 同上 |
| `home/knowledge/exports/<名>-<时间戳>.kb.json` | 导出文件 | 时间戳防覆盖 |
| `home/knowledge/sources/<库名>/part_NNNN.md` | 大文件分段落盘的学习资料 | 按序编号 |
| `home/materials/`（**推荐**） | **你自己的原始学习资料**（PDF/PPTX/讲义等） | 自定 |

> 📁 **源文件放哪里最省事**：放在 **`home/` 的任意子目录**（推荐 `home/materials/`）。因为 Agent 的 `read_file` 只放行"**工作目录**"与"**`home/`（data_root）**"两类路径，超出范围会报 `⛔ 路径超出工作目录`。资料放在 home 下，既能被目录建库逐个读取，也能随整个程序目录便携迁移。

> ⚠️ **`kb.db` 是独立的 SQLite 文件**，不走 `home/memory.db`（长期记忆）。删 `kb.db` = 清空所有知识库；删单个库用 `/learn reset`（只清进度）或直接删库记录。

### 2.4 模型与 Key 在学习模式中的角色

| 操作 | 是否经过 LLM | 消耗 token |
|------|--------------|-----------|
| `/learn <文件/目录/名称>` 建库 | ✅ 是 | 是（抽取知识点、讲解、出题） |
| `/learn list` | ❌ 本地 | **零** |
| `/learn export` / `import` | ❌ 本地 | **零** |
| `/learn reset` | ❌ 本地 | **零** |
| `/summary`、`/stop` | ✅ 是 | 是（生成总结/Bento 文案） |

结论：**"管理类"命令完全免费且瞬间完成**，只有"建库与教学"才消耗 token。

### 2.5 多通道使用要点

`/learn` 在 TUI、微信、企业微信、Telegram 上**行为一致**（同一套路由与会话）。

- 微信通道的配置步骤见 **§1.3 快速配置微信通道**（扫码登录即可）；企微 / Telegram 同理，先在 `gateway setup` 中启用对应通道；
- 非 TUI 通道在建库期间会收到**每分钟心跳**（TUI 因有实时工具进度而跳过）；
- TUI 有实时工具进度条，能看到 `kb_create` 正在跑；外部通道只能看到心跳，请耐心等待大文件建库。

### 2.6 配置自检与常见配置错误

| 现象 | 原因 | 处理 |
|------|------|------|
| 提示找不到配置 / 读的是空配置 | 配置不在 exe 同目录 | 把 `config.toml`、`.env` 放到与 `rhermes.exe` **同级** |
| `/learn` 建库时报模型相关错误 | Key 未填或模型不可用 | 检查 `.env`；`rhermes config check` |
| 改了 `review_floor` 不生效 | 修改了非当前 exe 目录的配置 | 确认改的是**运行中那个 exe** 旁边的 `config.toml` |
| 换了盘后知识库"消失" | 数据在旧目录的 `home/` 下 | 把整个 `home/` 连同程序一起迁移 |

## 第 3 章 使用详解

### 3.1 命令总览

| 命令 | 作用 | 中文别名 |
|------|------|----------|
| `/learn <文件路径>` | 从文件内容建库（库名 = 文件名去扩展名） | — |
| `/learn <目录路径>` | 遍历目录内文件建库（库名 = 目录名） | — |
| `/learn <名称> [主题提示]` | 存在则续学（带进度）；不存在则按主题新建 | — |
| `/learn list` | 列出所有知识库与进度 | `/learn 列表` |
| `/learn export <名称> [--kb]` | 导出（默认含学习记录；`--kb` 只导库结构） | `/learn 导出` |
| `/learn import <路径> [--as 新名]` | 导入 `.kb.json` | `/learn 导入` |
| `/learn reset <名称>` | 复位学习进度（保留知识结构） | `/learn 复位` |
| `/summary` | 阶段总结（**不退出**学习模式） | `/summary` |
| `/stop` | 退出学习模式并生成 Bento 战绩 | `/stop` |

> 什么都不带直接 `/learn`，会打印完整用法帮助。

### 3.2 建库的四条路径

#### 路径 ①：单文件建库

```
/learn home/materials/计算机网络.pdf
```

- 库名自动取 **文件名去扩展名**（`计算机网络`）；
- 若同名库已存在 → **自动转为续学**，不会重复建库；
- 支持格式：文本（`txt/md/html/csv/json`）与二进制文档（`pdf/docx/pptx/xlsx`，含图片 `png/jpg/...`）；
- 📁 资料**建议放在 `home/` 子目录下**（如 `home/materials/`），以避开 `read_file` 的"工作目录 / home"边界限制。

#### 路径 ②：目录建库

```
/learn home/materials/操作系统
```

- 遍历目录下的文件（扩展名白名单：`txt/md/pdf/docx/pptx/xlsx/html/csv/json`）；
- 库名取 **目录名**；
- 内部会为每个文件标注读取方式（二进制走解析、文本走分段读取），要求逐个读完；
- ⚠️ **目录模式最需要留意路径**：Agent 要逐个 `read_file` 读源文件，若目录不在**工作目录**或 **`home/`** 下，会报 `⛔ 路径超出工作目录`。把资料目录放进 `home/`（如 `home/materials/操作系统`）即可根除。

#### 路径 ③：名称 + 主题（让模型从零建库）

```
/learn 数据结构 我零基础，请从最基本的概念开始
```

- 库不存在时，模型会先询问/确认主题，再用 `kb_create` 建库并出图；
- 节点规模由内容决定（建议 8–40 个知识点）。

#### 路径 ④：导入已有库

```
/learn import D:\备份\计算机网络-20260930-1600.kb.json
```

详见 §3.8。

### 3.3 大文件分段机制（为什么大文件也不会漏内容）

`/learn` 对小文件与大文件走**两条不同的通路**：

| 条件 | 处理方式 |
|------|----------|
| 内容 ≤ **24000 字符** | 全文内联注入，模型直接通读 |
| 内容 > **24000 字符** | **强制分段**：按行切块，每块 ≤ **20000 字符**（不拆半行），逐块落盘到 `home/knowledge/sources/<库名>/part_0001.md`、`part_0002.md`… |

大文件模式下，模型会收到**完整分段清单**，被要求**逐段 `read_file` 读完，一段都不能遗漏**，全部读完后才 `kb_create` 一次性建库。

**三重保障**：

1. **读入分流**：二进制文档（pdf/docx/pptx/xlsx/png…）先解析为文本；解析失败退回文本读取，再失败则明确报错（不会静默给空内容让模型瞎编）。
2. **落盘中转**：分段落到 `sources/`，读取路径被放行（与工作目录同信任级）。
3. **建库闭环校验**：建库完成后程序会**回查数据库**确认真的建成——
   - 成功阈值：**至少 5 个知识点**（`KB_BUILD_MIN_NODES`）；
   - 未达标则注入重试指令，**最多重试 3 次**（`KB_BUILD_MAX_RETRIES`）；
   - 仍失败会明确告知："可再发一次 `/learn <文件路径>` 重试，或用 `/learn <名称>` 手动指导建库"。

> 建库期间（非 TUI 通道）会**每分钟推送一次心跳**，告诉你"已建 N 个知识点，仍在补充完善"。

### 3.4 学习循环（`/learn` 到底怎么"教"）

进入学习模式后，教学规则由内嵌的**导师规则块**驱动，核心是**"一段一问、讲完即测、不问你继不继续"**：

1. 用 `kb_learn` 取下一个知识点 → 围绕摘要讲解，结合"前置/后续"关联承上启下；
2. 用户回答后出 **1–2 道题**验证，**严格判分**：
   - 全对 → **90–100**
   - 答对部分 → **50–79**
   - 没答上 → **0–49**
3. 立即用 `kb_quiz` 回填（`topic / node / score / question / answer`）；
4. **判分后不询问"是否继续"**，直接 `kb_learn` 取下一个，循环到全部掌握或你喊停；
5. 每 **3–5 个节点**自动 `kb_graph` 刷新图谱，并把 HTML 路径给你；
6. 你闲聊时，简短回应一句后**立刻拉回当前学习节点**；
7. 全部节点掌握度 ≥ 80% → 主动祝贺收官，`kb_stats html=true` 出 Bento。

**三种结束方式**：

| 命令 | 行为 |
|------|------|
| `/summary` | 出阶段报告（已点亮、平均掌握度、薄弱点），**保持学习模式**，可继续 |
| `/stop` | 退出学习模式，生成 Bento 战绩并给学习小结 |
| 学完全部节点 | 自动祝贺收官 |

### 3.5 掌握度与遗忘曲线（原理，决定你看到的所有数字）

#### ① 掌握度 `mastery`（历史基线，不衰减）

```
首次测验：mastery = 本次分数
其后每次：mastery = (旧 mastery × 40 + 本次分数 × 60) / 100
```

即**新测验占 60% 权重**。这个值代表"你历史上学得怎么样"，**不会随时间下降**。

**24 小时防刷分**：同一天、同一节点，**只取当日最高分**。所以一天内反复重考同一题想把分数刷上去是无效的。

#### ② 有效掌握度 `effective_mastery`（今天真实还记得多少）

```
retention = 2^(-Δt/S)              # 艾宾浩斯指数衰减
effective_mastery = round(mastery × retention)
```

- `Δt`：距上次复习的天数；
- `S`：记忆半衰期（天）——保留率降到 50% 所需时间。

**算例**：某节点 8 天前复习考了 90 分，`S = 2.5` 天：

```
retention = 2^(-8/2.5) ≈ 0.109
effective = round(90 × 0.109) ≈ 10
```

→ 当前有效掌握度只剩 **10%**，远低于红线 60，会被**优先安排复习**。这就是"图谱节点会自动变浅"的原因。

#### ③ 半衰期 `S` 随分数伸缩

| 测验分数 | S 调整 | 含义 |
|----------|--------|------|
| ≥ 90 | ×2.5 | 极好，间隔大幅延长 |
| 70–89 | ×2.0 | 良好 |
| 50–69 | ×1.5 | 一般 |
| < 50 | ×0.7 | 遗忘严重，缩短间隔促重学 |

S 钳制在 `[0.5, 180]` 天（避免过短"每分钟复习"或过长"永不复习"）。

#### ④ SM-2 难度系数 EF（区分"难知识点"和"简单知识点"）

只看分数不够——**反复考 60 分的难点**和**轻松考 60 分的简单点**，间隔不该一样。EF 用来表达知识点的"顽固程度"：

```
质量分折算：q = round(score / 20)          # 100 分制 → 0–5
EF 递推：   EF' = EF + 0.1 - (5-q)(0.08 + 0.02(5-q))
钳制范围：  [1.3, 2.8]，初值 2.5（中性锚点）
```

| 得分 | q | EF 变化 | 含义 |
|------|---|---------|------|
| 100 | 5 | +0.10 | 越考越轻松 |
| 80 | 4 | 0 | 难度不变 |
| 60 | 3 | −0.14 | 开始变难 |
| 40 | 2 | −0.32 | 明显吃力 |
| 20 | 1 | −0.54 | 高难点 |
| 0 | 0 | −0.80 | 极难，间隔大幅压缩 |

EF 通过乘数作用于半衰期（以 2.5 为中性，乘数为 1）：

```
ef_mult = clamp(EF / 2.5, 0.5, 1.2)
new_stability = S × 分档系数 × ef_mult    # 钳制 [0.5, 180]
```

> **重要**：间隔更新使用**本次测验前的旧 EF**。这保证"首次测验时 EF 必为中性 2.5"，因此**第一次复习间隔与旧版本严格一致**（向后兼容锚点）。你会在 `kb_learn` 的标题里看到 `难度 EF x.x`——**越低越难**，模型据此调整讲解深度。

#### ⑤ 选点优先级（决定"下一个学什么"）

```
① 到期复习（effective < review_floor）：effective 升序（最遗忘的优先）
② 未学过（mastery = 0）：层级升序 → id 升序
③ 薄弱巩固（60 ≤ effective < 80）：effective 升序
④ 无（effective ≥ 80）：该库学习完成
```

### 3.6 图谱与 Bento

**知识图谱**（`kb_graph` → `home/knowledge/graphs/<库名>.html`）

- 浏览器打开，节点按**当前有效掌握度**着色（非历史值）：
  - 灰 = 未学习
  - 黄 = 初识
  - 浅绿 = 掌握中
  - 亮绿 = 精通
- **节点颜色会随遗忘自动变浅**——今天打开图谱，看到的就是"今天还记得多少"。
- 终端同时给出一份分层概览，符号含义：`░` 未学 / `◐` 初识 / `◉` 掌握中 / `●` 精通。

**Bento 战绩面板**（`kb_stats`）

- 终端版：2×4 网格，含「待复习 N 个 · 最紧急 X（m%）· 平均保持率 r%」；
- HTML 版（`/stop` 或 `kb_stats html=true`）：额外含「⏰ 待复习」「💧 平均保持率」两格。

**分档定义**（图谱与终端共用）：`0`=未学习 · `1–49`=初识 · `50–79`=掌握中 · `≥80`=精通。

### 3.7 统计与阶段总结

- **`/summary`**：随时可用，**不退出**学习模式。输出已点亮节点、平均掌握度、薄弱点，然后问你是继续还是休息。
- **`/stop`**：退出学习模式，调 `kb_stats html=true` 生成 Bento，把 HTML 路径和简短学习小结一起给你。
- **`kb_stats` 里的关键字段**：
  - 「已点亮 N/M」= 曾学过的节点数（`mastery > 0`，不衰减）
  - 「平均掌握度」= 当前**有效**掌握度均值（会随遗忘下降）
  - 「平均保持率」= 平均 `retention`
  - 「到期该复习」= `effective < review_floor` 的节点清单（前 5 条）

### 3.8 导出 / 导入 / 复位

#### 导出

```
/learn export 计算机网络            # 完整版：库结构 + 学习记录（掌握度/测验史/会话）
/learn export 计算机网络 --kb       # 纯库版：只含节点/关系/层级，适合分享他人从零学
```

- 落盘：`home/knowledge/exports/<名称>-<时间戳>.kb.json`，回复中给绝对路径；
- 导出格式：`format = "rhermes-kb"`，`version = 3`。

#### 导入

```
/learn import D:\备份\计算机网络-20260930-1600.kb.json
/learn import D:\备份\xxx.kb.json --as 计算机网络2    # 目标库重名时换名导入
```

| 场景 | 行为 |
|------|------|
| 目标库不存在 | 完整还原（含学习记录，若文件携带） |
| 目标库已存在 | 报错，提示用 `--as` 换名 |
| 边引用了不存在的节点 | 自动跳过并计数 |
| `format`/`version` 不匹配 / JSON 解析失败 | 明确报错 |
| 导入完成 | 重算拓扑层级，给出导入报告 |

写入使用 **SQLite 事务**，任一步失败整体回滚，不会留半成品库。

#### 复位

```
/learn reset 计算机网络
```

清零掌握度/复习次数，清空测验记录与学习会话，**保留知识点与关系结构**，可从头再学。与 `/stop`（只结束会话）完全不同。

> 📌 导出文件里的表间关联一律用**节点名**（库内保证唯一），不导出内部 ID——因此换机导入天然不会有 ID 冲突。⚠️ `sources/` 里的原始分段资料**不打包进 JSON**（教学只依赖节点摘要，不影响续学）。

| 时段 | 建议动作 |
|------|----------|
| 首次 | `/learn <资料>` 建库，通读图谱结构 |
| 学习日 | `/learn <库名>` 续学，跟着讲解-提问-判分循环走 |
| 中途 | 想歇一下用 `/summary`（不退出），或直接 `/stop` |

| 换机/分享 | 完整版导出→导入续学；`--kb`→他人从零学 |

## 第 4 章 常见问题解决方案（FAQ）

### A. 建库类

**A1｜模型"凭文件名瞎编"内容**
- **原因**：文件是二进制（pdf/docx/pptx…），历史版本读取失败会被静默当空内容。
- **解决**：现版本已修复（二进制走解析、失败明确报错）。若仍出现，说明**文档解析失败**（见 G1）；可先把文档导出为纯文本再建库。

**A2｜建库节点太少 / 内容明显不全**
- **原因**：内容过长导致模型输出被截断。
- **解决**：现版本已自动兜底——先用 `kb_create` 建核心骨架（8–15 节点），再用 `kb_append` 分批追加；程序还会回查数据库，**不足 5 个节点自动重试最多 3 次**。若最终仍失败，按提示**再发一次 `/learn <路径>`**，或 `/learn <库名>` 手动指导补建。

**A3｜提示"知识库 'xxx' 已存在"**
- **原因**：库名与已有库重名（`topic` 名唯一）。
- **解决**：这不是错误——同名时 `/learn <名称>` 会**自动续学**。若要并存两个不同来源的同名库，先用 `/learn import ... --as 新名`，或给文件改名后再建。

**A4｜提示"路径不存在" / "不是普通文件或目录"**
- **原因**：路径写错，或指向了特殊文件。
- **解决**：用绝对路径；`~` 会被展开为主目录。TUI 里注意反斜杠转义。

**A5｜目录建库时有些文件没被收录**
- **原因**：目录模式只收白名单扩展名：`txt / md / pdf / docx / pptx / xlsx / html / csv / json`。
- **解决**：把资料转成上述格式之一；图片类文档请先转 PDF。

**A6｜报错 `⛔ 路径超出工作目录`**
- **原因**：资料路径既不在**工作目录**下，也不在 **`home/`（data_root）** 下，Agent 的 `read_file` 拒绝读取。**目录建库时最容易踩到**（单文件建库一般不受影响，因为内容会被内联或落盘到 `sources/`）。
- **解决**：把资料（或整个资料目录）移动到 `home/` 的子目录下，如 `home/materials/`，再执行 `/learn home/materials/<名称>`。

### B. 学习类

**B1｜提示"当前不在学习模式中"**
- **原因**：`/summary` 只在学习模式内可用。
- **解决**：先 `/learn <名称>` 或 `/learn <文件路径>` 进入，再 `/summary`。

**B2｜学到一半卡住不推进**
- **原因**：多为等待你作答，或模型在等待确认。
- **解决**：学习模式**不问你"是否继续"**（规则要求判分后直接取下一个）。若确实停了，回一句"继续"或再发 `/learn <库名>` 续学。

**B3｜它只是口头问，没有真正记录分数**
- **原因**：极少数情况下模型未调用 `kb_quiz`。
- **解决**：明确说"请用 kb_quiz 记录这道题的分数"。判分回填后终端会出现 `已记录：'xx' 掌握度 -> NN%`。

**B4｜闲聊被"拉回"，感觉太硬**
- **原因**：这是设计行为（防止偏离学习目标）。
- **解决**：想真正休息用 `/stop`；只是提问/确认用普通消息即可，模型会简短回应后回到节点。

### C. 掌握度与复习类

**C1｜为什么我的分数不涨？**
- **原因**：**24 小时防刷分**——同一节点同一天只取最高分；得分 ≤ 当日最高分时"本次不计入"。
- **解决**：换天再测，或先推进别的节点；你会在输出里看到"今日该节点已有更高分，本次不计入"。

**C2｜掌握度怎么反而变低了？**
- **原因**：这是**正常现象**——「平均掌握度」用的是**有效**掌握度，会随时间衰减。历史 `mastery` 并未下降。
- **解决**：无需处理；`kb_learn` 会自动把衰减严重的点排到最前。

**C3｜明明学过了，却总让我复习**
- **原因**：该节点 `effective < review_floor`（默认 60），被判为"已显著遗忘"。
- **解决**：正常复习即会提升 `S` 与 EF，间隔会逐渐拉长。若觉得太频繁，把 `review_floor` 调低（§2.2）。

**C4｜该复习的没有排上**
- **原因**：选点优先级中，「到期复习」优先于未学/巩固，但**只有 `effective < review_floor` 才进入复习队列**。
- **解决**：`kb_stats` 里的「到期该复习」清单就是队列；若为空说明当前无需复习。

**C5｜`/learn reset` 后库怎么还在？**
- **原因**：`reset` 只清**学习进度**（掌握度/测验史/会话），**保留知识点结构**——这是有意设计。
- **解决**：想彻底删除库，删 `home/knowledge/kb.db` 中对应记录（或备份走后重建）。

### D. 图谱 / Bento 类

**D1｜图谱/Bento 文件在哪？**
- 图谱：`home/knowledge/graphs/<库名>.html`
- Bento：`home/knowledge/bento/<库名>.html`
- 每次生成时**回复里都会给出绝对路径**，直接复制到浏览器打开。

**D2｜中文库名变成了一串下划线**
- **原因**：文件名清洗规则会把非字母数字字符转 `_`。
- **解决**：属正常现象，不影响内容；检索文件时按此规则找（如 `计算机网络` → `________`）。建议库名优先用简短中文或英文。

**D3｜节点颜色一直不变浅**
- **原因**：颜色取决于**有效掌握度**，而 `Δt` 按**整天**计算，刚建库/刚复习当天不会变化。
- **解决**：隔天再看；或确认节点确实"很久没复习"。

### E. 导入 / 导出类

**E1｜导入报"目标库已存在"**
- **解决**：`/learn import <路径> --as 新名字`。

**E2｜导入报格式/版本不匹配或 JSON 解析失败**
- **原因**：文件不是 `.kb.json`，或被手工改动破坏。
- **解决**：使用 `/learn export` 的原始产物；不要用文本编辑器修改。

**E3｜导入后关系（边）少了**
- **原因**：边引用了不存在的节点会被**自动跳过并计数**（正常容错）。
- **解决**：看导入报告里的跳过条数；若异常多，说明导出文件本身不完整。

**E4｜为什么 `sources/` 里的原始资料没跟着走？**
- **原因**：设计上**不打包**（教学只依赖节点摘要，续学不受影响）。完整打包（zip）列为后续扩展。
- **解决**：需要的原始资料请单独拷贝 `sources/<库名>/` 目录。

### F. 性能与成本类

**F1｜哪些命令不花 token？**
- `/learn list`、`export`、`import`、`reset` 均为**纯本地操作，零 token、瞬间完成**。只有建库与教学走模型。

**F2｜大文件建库很慢、很贵**
- **原因**：>24000 字符会分段，模型需逐段读完再抽取。
- **解决**：把资料**聚焦单一主题、控制体量**（一次一份讲义/一章），比一次性丢一本 500 页 PDF 效果好得多，也更省。

**F3｜建库期间界面像卡住了**
- **原因**：正在解析/抽取知识点。
- **解决**：TUI 看实时进度条；外部通道看**每分钟心跳**。耐心等待，别重复发命令（可能触发续学分支）。

### G. 环境类

**G1｜PDF 解析失败**
- **原因**：本机缺少 PDF 解析所需组件（如 pdfium），属环境问题而非数据问题。
- **解决**：把 PDF 转成 docx/txt 后再建库；或补齐解析组件。

**G2｜换盘/换机后知识库不见了**
- **原因**：数据在**原目录的 `home/`** 下，未随程序迁移。
- **解决**：迁移时把**整个程序目录（含 `home/`）**一起拷贝；或先用 `/learn export` 导出再在新机 `import`。

**G3｜提示技能不存在（如 `knowledge-base-tutor`）**
- **说明**：建库提示词里引用的 `knowledge-base-tutor` 技能**并未随仓库提供**；实际教学规则由程序内嵌的导师规则块驱动。
- **解决**：**无需安装任何技能**，`/learn` 开箱即用；忽略该名称即可。

## 第 5 章 进阶与最佳实践

### 5.1 资料准备建议

- **统一放进 `home/` 子目录（首要建议）**：建库前先把资料集中放到 `<exe_dir>/home/materials/`（或 `home/` 下任意子目录）。这既保证 Agent 能越权读取（`read_file` 只放行工作目录与 `home/`），又让资料与知识库一起便携迁移——换机只需拷整个程序目录。
- **单一主题、结构清晰**：一个库 = 一个主题（一份讲义、一章、一门课）。混装会让你在复习队列里来回跳。
- **优先可复制文本**：docx/pptx/md/txt 的抽取质量远好于扫描版 PDF。
- **避免超长文档**：与其丢一本 500 页 PDF，不如按章建多个库——更省 token，复习也更聚焦。
- **给关键概念写清摘要**：节点摘要会直接作为讲解依据，摘要质量决定教学深度。

### 5.2 多库组织与命名

- 库名即检索键，且**唯一**；建议用「学科-层级」式命名，如 `数据结构-树`、`数据结构-图`。
- 中文库名可用，但生成的 HTML 文件名会被清洗（见 D2）。
- 定期 `/learn list` 巡检：一眼看出每个库的点亮进度与待复习数。

### 5.3 教师分发流程

```
教师：/learn D:\讲义\计算机网络.docx        # 建库
      /learn export 计算机网络 --kb          # 纯库导出（不含教师自己的学习记录）
      ↓ 把生成的 .kb.json 发给学生
学生：/learn import D:\计算机网络-xxx.kb.json # 从零开始学，进度互不干扰
```

- 用 `--kb` 而非完整版，避免把教师的掌握度/测验史带给学生；
- 学生可另存为不同库名（`--as`）以保留个人进度；
- 若仍需使用旧版本导出的 v1/v2 文件，新版本可**向后兼容读取**（缺失字段取默认值）。

### 5.4 `review_floor` 场景化配置

| 使用者 | 建议 | 理由 |
|--------|------|------|
| 考研/期末冲刺 | 75–85 | 要求高保持率，宁可多复习 |
| 日常教学班 | 60（默认） | 平衡教学节奏 |
| 兴趣泛读 | 40–50 | 降低复习压力 |

改配置后**立即生效**（下次 `/learn` 起按新红线调度）；已存库的历史数据不受影响。

### 5.5 与教学班（edu）的分工

- `/learn`：**个人自学**工具——知识图谱 + 间隔复习，进度只属于你自己。
- edu 教学班：**班级协同**工具——教师建课建班、学生加入、答疑与作业。
- 二者可组合：教师先用 `/learn` 建好知识库并 `--kb` 分发，作为班级学习的预习/复习材料。

## 附录

### 附录 A · 公式速查表

| 名称 | 公式 | 说明 |
|------|------|------|
| 掌握度（EMA） | 首次 = 分数；其后 `(旧×40 + 新×60)/100` | 新测验占 60%，不衰减 |
| 保持率 | `retention = 2^(-Δt/S)` | Δt = 距上次复习天数 |
| 有效掌握度 | `effective = round(mastery × retention)`，钳 [0,100] | 决定分档、着色、是否到期 |
| 半衰期分档 | ≥90×2.5 · 70-89×2.0 · 50-69×1.5 · <50×0.7 | 再钳 [0.5,180] |
| 质量分 | `q = round(score/20)` | 100 分制 → 0–5 |
| EF 递推 | `EF' = EF + 0.1 - (5-q)(0.08+0.02(5-q))`，钳 [1.3,2.8] | 初值 2.5；用**测验前旧 EF** 更新间隔 |
| 半衰期更新 | `S' = S × 分档系数 × clamp(EF/2.5, 0.5, 1.2)` | 钳 [0.5,180] |
